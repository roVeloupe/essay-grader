## 1. 项目概述

### 1.1 背景与目标
教师常需批量批改手写作文的扫描图片，传统流程费时费力且易因字迹/拍照模糊产生识别误差。本项目提供一个 **Windows 桌面应用**：

1. 导入 N 张作文扫描图片，**按文件名排序**处理与输出；
2. 自动识别图片中的 **标题、正文、学生姓名**（含多页拼接）；
3. 对识别文本进行**纠错 + 校对**，并**与原始图片复核比对**，降低识别误差；
4. 对确认无误的文本，按**用户自定义批阅标准**输出 **分数、优点、缺点、修改建议**；
5. 所有结果按原文件名顺序汇总、可编辑、可导出。

### 1.2 一句话定位
> 一个"看图作文 → 识别校对 → 按标准批阅"的一站式 WinUI3 桌面工具，AI 能力全部由 StepFun `step-3.7-flash` 多模态模型完成。

## 5. 核心业务流程

```
[导入 N 张扫描图] → [按文件名排序]
      │
      ▼
① 内容识别：图片→base64→step-3.7-flash(一次请求) → {标题, 姓名, 正文, 逐句置信度}
      │
      ▼
② 纠错与校对：
      ├─ 高置信度句子 → 标记"确认"
      ├─ 低置信度字符/句 → 回溯原图区域复核 → "已修正" 或 "存疑待人工"
      └─ 语句不通顺处 → 不改变原意润色 → "已润色(标注)"
      │        （全程与原文图片对照，可人工接受/忽略/撤销）
      ▼
③ 批阅：按选中批阅标准 → step-3.7-flash 输出 {总分, 各维度分, 优点, 缺点, 修改建议(引用原文)}
      │
      ▼
④ 汇总：按文件名顺序排列所有识别文本 + 批阅结果
      ▼
⑤ 编辑/查找 / 导出 Word·PDF·Markdown
```

单篇处理管道是一个**有状态机**，同一篇作文始终保持：`待识别 → 识别中 → 已识别 → 校对中 → 已校对 → 批阅中 → 已批阅` 七态流转。多篇之间按文件名顺序发起，可配置并发。

## 6. StepFun 对接设计

### 6.1 基本参数
| 项 | 值 |
| --- | --- |
| Base URL | `https://api.stepfun.com/v1` |
| 鉴权 | `Authorization: Bearer <API_KEY>` |
| 模型 | `step-3.7-flash`（多模态，原生 base64 视觉） |
| 推理强度 | `reasoning_effort`: `none` / `low` / `medium` / `high`（校对场景建议 `high`，速度场景 `low`） |
| 上下文 | 约 256K（单篇作文识别轻松容纳） |

### 6.2 识别请求示例（此时即可用）

```csharp
// StepFunClient.RecognizeEssayAsync(base64Image, fileId)
var payload = new
{
    model = "step-3.7-flash",
    reasoning_effort = "high",
    messages = new[]
    {
        new { role="system",
              content = "你是手写作文扫描图的识别与校对助手。识别图片中的标题、作者姓名、正文。" +
                        "逐句给出置信度(0-1)。只为纠正识别误差，不改变原文意思。" },
        new { role="user",
              content = new object[]
              {
                  new { type="text",
                        text = "请识别这张作文扫描图。要求：\n" +
                               "1) 标题、作者姓名、正文分开返回\n" +
                               "2) 正文按自然句 a) b) c) 列出并标注置信度\n" +
                               "3) 对疑似错字/难辨字额外给出原文区域描述" },
                  new { type="image_url",
                        image_url = new { url = $"data:image/jpeg;base64,{base64Image}" } }  // 原生 base64
              } }
    },
    temperature = 0.2,
    response_format = new { type = "json_object" }   // 强制结构化 JSON
};
```

### 6.3 统一返回 JSON 契约（识别阶段）
```json
{
  "page_count": 1,
  "title": { "text":  "春天在哪里",  "confidence": 0.97 },
  "author": { "text": "王小明",      "confidence": 0.96 },
  "body":   {
     "sentences": [
        {"id":"a1","text":"春天在哪里？我问桃树……","confidence":0.98,"region":"r1"},
        {"id":"a2","text":"终于，我在田野里找到了春天。","confidence":0.61,"region":"r3"}
     ]
  },
  "low_confidence": ["a2"]
}
```
- `region` 为模型给出的图像区域标识，用于原图框选复核（FR-07）；
- `confidence < 阈值(默认 0.8)` 自动进入"待复核"清单（FR-08/FR-10）。

### 6.4 纠错 / 校对比对提示词要点
一次请求内完成「纠正 + 对照原文 + 不通顺润色」，并区分动作类型：

```text
请你作为批改前的中文校对助手，对照上面这张作文原图：
1. 若识别文本与原图不符，给出 correct = 正确文本。
2. 若句子不通顺（可能是漏字/错字导致），在不改变原意前提下给出 polish = 润色文本。
3. 若无法判断处给出 need_verify = true，交给人工。
每条输出: {id, verdict: correct|polish|verify|ok, text}
```

### 6.5 批阅请求提示词要点
```text
按下述批阅标准评分（逐维度满分见配置）：
内容立意(25)/语言表达(20)/结构条理(12)/卷面书写(3)，满分合计 60。
对每篇作文输出：总分、各维度得分、一句话等级、
优点(引原文)、缺点(对应失分维度)、修改建议(不改变原意)。
仅依据正文与标准，不要臆造原文没有的内容。
```

### 6.6 失败与重试
- 超时：默认 120s，`reasoning_effort=high` 可放宽；
- 重试：500/429/网络错误 → Polly 指数退避（1s/2s/4s，最多 3 次）；
- 一致性：后续批阅会话携带同一篇作文的**最终确定文本**，保证结果稳定。

## 7. 纠错与校对比对设计（重点）

### 7.1 三级置信处置策略
| 级别 | 置信度 | 处置 |
| --- | --- | --- |
| A（通过） | ≥ 0.9 | 直接标记"识别确认" |
| B（复核） | 0.7 – 0.9 | 进入"待复核"，回溯原图区域二次确认 |
| C（存疑） | < 0.7 | 进入"待人工"，默认不自动写入，需教师确认 |

### 7.2 与原图比对的方式
1. **左右对照视图**：左窗显示原图（支持缩放/框选），右窗显示识别文本；点击文本中带颜色标记的句子，左窗自动框出对应原图区域（FR-09）。
2. **区域映射**：识别接口返回 `region`，程序据此在原图绘制可点击的高亮框。
3. **编辑冲突保护**：人工修改后标记 `已人工修改`，后续重批不再覆盖该句。

### 7.3 不通顺润色的约束（防止 AI 改写原意）
- 润色请求中显式强调"只修正语病/补全，不添加新情节、不改变主题与情感";
- 每次润色输出同时返回 `original→polished` 对照，界面以 `<del>` 底色展示，教师可一键接受/忽略/撤销（FR-11）。

## 8. 批阅标准管理设计

### 8.1 数据模型（可随时调整）
```text
StandardTemplate
 ├─ Id, Name, TotalScore, IsDefault, UpdatedAt
 └─ Dimensions: List<GradeDimension>
      GradeDimension: { Name, MaxScore, Rule }
                        ↑ Rule 是一段给 AI 的评分解读提示词
```

### 8.2 使用方式
- 工具栏「标准」进入管理页（预览图 ④）：可**新建 / 重命名 / 复制 / 删除**模板，调整每个维度的**名称、满分数值、评分规则**（FR-12）；
- 26 号模板维度合计会自动校验 = 总分（超分/缺分会提示）；
- 「设为默认套用」后，新批阅任务默认采用该标准；
- 批阅中**切换标准 → 一键重批**（FR-15）。

## 9. 文件排序与批量输出

### 9.1 排序规则
- 默认按**图片文件名**做自然排序（自然数排序，`2` 排在 `10` 前），例如：
  `IMG_1.png < IMG_2.png < IMG_10.png`（非字典序）。
- 一张作文多页时，以主文件名归组，组内按副序号排。

### 9.2 输出
- 批阅结果列表与导出的文档均**严格沿用该顺序**（FR-16）；
- 列表每行显示：序号、文件名、标题、作者、总分、等级、状态；
- 导出可选：单篇 / 全部合并（Word / PDF / Markdown）（FR-17）。

### 9.3 保存位置可配置（FR-19 / FR-20）
批阅结果与导出文档的**保存位置**由用户自行指定，不写死到系统目录，提供清晰的两类设置：

**① 批阅结果自动保存目录（`resultsDir`）**
- 每篇作文「保存结果」时，默认写入该目录，例如：
  `D:\教案\作文批改\结果\1_王小明_春天在哪里.批阅报告.docx`；
- 若未设置，回退到应用数据目录 `%LocalAppData%\EssayGrader\exports\`。

**② 导出文档目标目录（`exportDir`）**
- 批量导出（合并文档 / 全部单篇）时写入该目录；
- 子目录按批阅批次自动管理：`批次_yyyyMMdd_HHmmss\`。

**两种保存模式（设置页切换，FR-20）**
| 模式 | 行为 |
| --- | --- |
| 每次询问 | 导出时弹出系统文件夹选择器（`FolderPicker`），由用户临时指定目标目录 |
| 始终保存到默认目录 | 直接写入 `resultsDir` / `exportDir`，不弹窗 |

**配置与持久化**
- 在「设置」页新增「保存位置」分组，含两项目录选择器（文本框 + 「浏览…」按钮）；
- 选择目录采用 WinUI3 系统级 `FolderPicker`，避免手工输入路径出错；
- 配置写入 `settings` 表（`results_dir` / `export_mode` / `export_dir`），Key 加密无关，路径明文即可；
- 目录不存在时程序自动创建；无写入权限给出明确错误提示。

- 图片显示用 `Image.Source` 绑定缩略图，识别用 `ItemsRepeater` 渲染句子并叠加着色（置信度颜色）；
- 设置可用 `SettingsCard`（CommunityToolkit）快速搭建。

## 15. 附录：风险与注意事项
1. **手写识别难度**：潦草/低清图可能长期处于"待人工"，需保留清晰原图复核能力；
2. **多模态成本**：每次复核都重传 base64，可缓存同一页的识别结果，避免重复计费；
3. **隐私**：作文含学生信息，API Key 与内容默认仅存本地，不上传第三方存储；
4. **内容边界**：润色与建议由 AI 生成，终审权在教师，务必保留"让人工接受/忽略"的兜底。
